# 09.10 디자인 검토 — 구현 가능한 수정사항

## 검토 범위와 제한

사용자가 공유한 Claude 디자인은 로그인 화면으로 전환됐다. 대신 PC에 저장된 동일 이름 `태양광 대시보드 리디자인.dc.html`을 브라우저에서 열어6개 주요 메뉴를 확인했다. 실제 확인 화면은 약1250×720 뷰포트이다. 공유본 최신 버전과 동일함은 미확인. 화면의09-03 수치들은 디자인 샘플이며09-10 라이브 측정값으로 사용하지 않는다.

피그마 연결 계정 확인 및 [검토 파일](https://www.figma.com/design/hvOVi9YKsqMOkoniRxgZiK) 생성까지 됐지만, 화면 가져오기는 외부 편집 상태 생성에 대한 권한 심사에서 차단됐다. **파일은 아직 디자인 가져오기 미완료**다. 우회하지 않고 승인 후 이어간다. 아래는 검토/수정 요구사항이며 제품에 반영 완료했다는 뜻이 아니다.

## P0 — 디자인이 틀린 판단을 유도하는 문제

### 1. NWP 결측이 모든 Shadow를 막는다는 문구

확인: 종합현황·예측결과·모델검증·수집에서 반복적으로 ‘NWP 복구 이후 Shadow 개시’를 표시한다. 초단기 탭에도 동일 문구가 나온다.

수정: 모델별 필수 입력 의존성을 manifest에서 가져와 상태를 계산한다. 초단기는 발전 lag/ASOS, 단기는 해당 후보의GRID/NWP 등 실제 목록을 표시한다. ‘현재 선택 모델의 필수 ASOS가3시간 기준 초과 — 예측 대기’처럼 원인과 영향을 연결한다. NWP 미사용 모델에 NWP를 차단 사유로 표시하지 않는다.

완료 기준: NWP가 결측이고 초단기 필수 입력이 유효한 테스트에서 초단기는 NWP 사유로 차단되지 않는다. 반대 조건에서는 ASOS 또는 lag 누락을 정확히 표시한다.

### 2. 용량 기준이 화면마다 바뀜

확인: 사이드바240.6kW, 발전성능 모델기준241kW. 기존 정책의240/219와 다르며 현재출력 비율의 분모가 불명확하다.

수정: 발전소등록/인버터합계/모델기준/명판검증 여부를 데이터 계층에서 별도 제공. KPI에는 ‘현재 출력 ÷ 모델기준219kW’처럼 분모를 명시한다. 최신 설비대장과 검증이 끝나기 전 임의로240.6 또는241로 확정하지 않는다. 실시간 출력비를 기간 에너지 기반 설비이용률과 혼용하지 않는다.

완료 기준: 모든 화면이 같은 정의 필드를 사용하고, 단순 반올림으로 기준 용량이 달라지지 않는다. 출처·기준일은 상세에서 확인 가능하다.

### 3. PR57%를 완결률54.2%인 날의 확정 성능처럼 강조

확인: ‘완결일’과‘완결률54.2%’가 함께 있고, ASOS 수평일사를 경사 보정 없이 써서 PR57%를 큰 숫자로 표시한다.

수정: 원래 PR 산정에 필요한 용량·적산구간·일사면·자료 완결성 확인 전에는 ‘참고 지표/산정 제한’으로 낮춘다. 요건 미충족이면 값 대신 사유를 표시하고 상세에서 실험값을 제공한다. IEC 기반 표준 PR로 검증된 것처럼 표시하지 않는다. 전체 태양광 발전효율과 인버터 AC/DC 변환효율도 구분한다.

완료 기준: 완결성 미달 날짜가 ‘완결일’로 보이지 않고, 수평일사 기반 참고치에 표준 성능비 확정 라벨이 붙지 않는다.

### 4. 다른 용량 인버터를 절대출력 평균으로 경고

확인: #3·#4가 평균보다 낮다고 빨간 음수와 점검 권고를 표시. #4−29.3%인데 ‘30% 이상’이라는 설명에도 포함돼 있다.

수정: 인버터별 용량 정규화 출력, 동일시각 유효 피어, 일사·저출력 시간 제외 조건으로 비교한다. 용량이 미검증이면 ‘단순 출력 차이 — 이상 판정 불가’로 중립 표시. 주파수0의 알려진 비유효 측정값은 알람에 쓰지 않고 원시값과 상태를 분리한다.

완료 기준: 등록 용량이 다른 정상 인버터에 단순 평균 때문에 고장 경보가 발생하지 않는다. 실제 임계값과 문장이 일치한다.

### 5. 수집 시도와 유효 수신을 혼동

확인: 최근12회 막대가 있으나 횟수·다음 재시도는 미수집이라 표시. NWP 결측100%인데 일부 막대는 녹색. 홈은5개 중4개 정상, 수집 화면은 정상3·결측1·미연결1.

수정: ‘연결 성공’과‘유효값 확보’를 별도 상태로 둔다. 마지막시도/마지막유효값/다음실행/지연마감/기준 발행시각 이전 사용가능 여부를 나눈다. 예시 막대는‘샘플’로 표시하거나 실제 로그가 없으면 제거. 요약 카운트는 동일한 데이터와 판정 함수를 사용한다.

완료 기준: HTTP 성공·값 전부 결측 사례는 정상 수집으로 녹색 표시하지 않는다. 모든 카드의 정상 개수가 동일하다. 마감초과는 색뿐 아니라‘지연’텍스트와 시간으로 표시한다.

## P1 — 화면 배치·가독성

### 종합현황

상단 경고의 짧은 영역에서 문장이 잘게 줄바꿈된다. 긴 설명을‘차단된 모델 수 · 원인 · 마지막 유효수신 · 확인’4요소로 줄이고 근거는 클릭 상세로 보낸다. 메인에는 핵심 KPI4개, 발전곡선1개, 현재 상태/이벤트 요약만 둔다. 시간은 ‘기준09-10 14:00 KST’와 경과시간으로 통일하고10:54 같은 날짜 없는 시각을 다른 날짜 데이터에 공통 적용하지 않는다.

### 예측결과

시계열 미생성 빈 박스가 큰 면적을 차지한다. 빈 상태에는 필수입력별 상태·다음 실행·대상시간을 보여준다. 백테스트 수치와 라이브 실측대조는 탭/라벨로 분리한다. 그래프 범례의‘공식 예측’은 후보 Shadow라면‘후보 Shadow’로 바꾼다. +24h/+48h 아래 실제 대상구간과 lead범위를 설명한다.

### 인버터별 현황

현재 테이블과 막대그래프가 같은 출력 정보를 반복해 하단 점검권고가 첫 화면 밖으로 밀린다. 표 안의 작은 막대만 유지하고 분포그래프는 상세탭으로 이동한다. 정규화 출력과 품질·최종수신을 우선 열로 두고 주파수·온도·원시값은 행 상세로 분리한다.

### 발전성능

손실분석은 실제 근거가 없으면 빈 탭/예상값을 만들지 않는다. 출력곡선 y축 단위를kW로 명시한다. 미래 영역의‘데이터 수신 대기’는 아직 관측 시각이 오지 않은 경우‘미래 시각’으로 바꾼다. 발전 에너지 적산구간/커버리지를 값과 가까이 둔다.

### 모델 및 검증 — 가로스크롤 실측 확인

모델표의 번들명이‘초/단/기’처럼 세로로 깨지고 오른쪽 패널이 화면 밖으로 나가 하단 가로스크롤이 생긴다. 표 컨테이너 `min-width:0`, 가변 열 비율과 이름 열 최소 폭을 설정한다. 우측 중복 오차그래프를 상세로 옮겨 모델표에 폭을 준다. 긴 버전명은 요약+툴팁, 숫자는 줄바꿈 금지·우측 정렬. 일간 kWh 지표를 nMAE/nRMSE(%) 헤더에 억지로 넣지 말고 지표명/값/단위를 별도 필드로 제공한다.

### 데이터수집 — 하단 겹침 실측 확인

고정 높이 때문에 KPX행과 설명이 겹친다. 상단5카드와 하단 같은 내용표 중 하나를 요약용으로 축소한다. KPX처럼 현재 예측에 필요 없는 미연결 피드는‘선택 연동’상세로 분리한다. 현재 필수 수집을 더 넓게 배치하고 날짜/시각 열을 정렬한다.

## P2 — 공통 디자인 규칙과 인수 테스트

- 기본 본문14~16px, 표13~14px, 보조12px 이상을 목표로 한다. 이는 이번 디자인 제안이며 프로젝트 학술 기준이 아니다. 글자를 줄여 억지로 한 화면에 맞추지 않는다.
- 주요 본문·경보의 명도 대비를 실제 측정한 뒤 확정한다. 이번 검토에서 대비 수치나 WCAG 통과를 측정했다고 주장하지 않는다.
- 데스크톱1440×900과1920×1080에서는 핵심 업무 한 화면·가로스크롤0을 목표로 하고, 작은 화면/200% 확대에서는 내용 손실보다 세로스크롤을 허용한다. ‘무조건 스크롤0’ 때문에 중요 정보가 잘리는 설계는 금지한다.
- 상태는 정상/지연/결측/미연결/검증중을 텍스트·아이콘·색으로 함께 표시한다. 주황은 일반 수치가 아니라 주의 상태로 절제해 사용한다.
- 버튼처럼 보이는 요소는 키보드 조작·포커스·클릭 동작을 연결한다. 비활성 기능은 비활성 이유를 표시한다.
- 테스트 장면: 정상수집, API연결실패, HTTP성공·전부결측, 일부인버터결측, 늦은수신, 예측없음, 실측미도착, 후보/공식 전환, 오래된스냅샷.

## 권장 작업 순서

① 상태·용량·수신시각 데이터 계약 → ② 모델표/수집표 넘침 수정 → ③ 빈 상태·오류 상태 → ④ 글자·간격·색 → ⑤ 실제 자료 연결 및 화면별 테스트. 디자인 샘플의 숫자를 운영 DB에 역으로 넣지 않는다.
