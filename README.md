# UCUBE PV Forecasting · Evidence-First Solar Prediction

광주·부안·김제·영광의 발전량, 인버터, ASOS·GRID·NWP 자료를 연결해 **수집 → 전처리 → 변수선정 → 모델학습 → 시간순 검증 → Shadow 관측**까지 기록하는 태양광 발전량 예측 연구 저장소입니다.

> **TL;DR** 이 저장소는 “모델이 만들어졌다”와 “실시간 운영에서 검증됐다”를 구분합니다. 모든 수치는 산출물·스크립트·매니페스트를 기준으로 확인하며, 근거가 없는 부분은 후보 또는 보류로 표시합니다.

## 프로젝트 한눈에 보기

| 구간 | 현재 상태 | 정확한 의미 |
|---|---|---|
| 초단기 +1~4h | 후보 번들·Shadow 기록 | NWP와 무관한 단기 운영 검증 트랙. 장기 안정성 승격은 별도 판정 |
| +24h | 4지역 재학습 후보·별도 Shadow 조립기 | 내일의 가용 시각을 풀링한 구간 예측. 정확히 24시간 뒤 한 점과 동일하지 않음 |
| +48h | 부안·김제·영광 후보 | 모레 구간 후보. 광주는 백필·검증 조건이 부족해 제외 |
| 월간 | 광주·영광 기준선 동일표본 비교 | GB-Huber는 실험 후보이며 공식 승격 보류 |
| 수집·NWP | NC 유효 수신 사례와 장애 로그 보유 | 전체 710일 NC 완성 또는 지속 정상 운영을 주장하지 않음 |

**후보(candidate)**는 오프라인 학습·누출감사를 통과한 산출물이고, **Shadow**는 기존 운영 예측과 분리해 실제 입력 가용성과 예측 생성 여부를 관찰하는 단계입니다. 어느 단계도 사용자 확인 전 운영 모델을 덮어쓰지 않습니다.

## 왜 이렇게 설계했나

- **발행시각 기준 누출 방지**: 예측 발행 이후에 도착한 관측·예보를 입력으로 사용하지 않고 실제 수신시각과 issue time을 함께 기록합니다.
- **시간순 검증**: 무작위 분할 대신 과거로 학습하고 이후 구간으로 평가하는 walk-forward/hold-out 구조를 사용합니다.
- **기준선 비교**: 지속성, 전년동월, 계절평균, 선형회귀, Ridge 등을 같은 평가표본에서 비교합니다.
- **결측·보간의 제한**: 짧은 공백만 허용하고 긴 공백은 구름 변화·설비 이상을 왜곡할 수 있어 학습·평가에서 별도로 표시합니다. 선형보간, 방송(broadcast), 결측 유지(NaN)는 구간별로 구분합니다.
- **공식 주장 절제**: 국내 학술 근거, 프로젝트 자체 실험, 운영 정책을 서로 섞지 않습니다.

## 변수와 데이터 흐름

~~~text
발전량·인버터 ─┐
ASOS 관측 ─────┼─> 시간 정렬·품질 점검·결측/이상치 기록
GRID 예보 ────┤
NWP/NC 예보 ──┘                         │
                                        ▼
                              후보 변수 구성
                                        │
                 상관분석 → VIF/쌍상관 점검 → 모델 비교
                                        │
                 시간순 백테스트 → 리크 감사 → 후보 번들
                                        │
                         분리된 Shadow·대시보드 관측
~~~

변수표의 원자료, 파생변수, 라이브 재현 가능 여부는 [종합 보고서](docs/REPORT.md)와 각 지역 문서에서 확인할 수 있습니다.

## 지역별 대표 검증 수치

아래 값은 지역별 문서와 매니페스트에 기록된 **동일 풀 비교**를 요약한 것입니다.

| 지역 | 구성 | MAE (kW) | RMSE (kW) | 해석 |
|---|---|---:|---:|---|
| 광주 | +24h 후보 | 11.492 | 17.750 | 09.10 파일 감사. 최신 라이브 평가는 NWP 결측으로 보류 |
| 부안 | v6 vs 기존 v5 | 49.24 vs 50.14 | 78.15 vs 97.47 | 동일 시간단위 풀에서 개선 |
| 김제 | v6 vs 기존 v1 | 41.15 vs 42.69 | 65.44 vs 85.50 | 동일 시간단위 풀에서 개선 |
| 영광 | v6 vs 지속성 | 27.58 | 45.74 | 지속성 대비 MAE 67.0%, RMSE 66.1% 개선 |

수치는 운영 성능 보증이 아닙니다. 후보 번들은 실제 입력 결측, 발행 지연, 계절별 표본을 추가로 통과해야 합니다.

## 재현 가능한 범위

저장된 월별 OOF 결과와 지표·그림은 다음 명령으로 다시 만들 수 있습니다.

~~~bash
python scripts/render_monthly_evidence.py
~~~

원시 발전소 DB, 인증키, 운영 스케줄러, 비공개 NC/로그가 필요한 전체 수집·재학습은 이 공개 저장소만으로 재현되지 않습니다.

## 공개 범위와 안전

- 공개: 비밀정보를 제거한 연구 코드, 검증용 요약, OOF 결과, 그림 출처와 매니페스트
- 비공개: API 키, 원시 발전소 DB·Excel·NC, 운영 로그, 배포용 모델 바이너리
- 코드 목록과 제외 사유: [source_inventory.json](docs/source_inventory.json)

## 현재 한계와 다음 판정

1. KIM NC API의 변수·파일 조회 장애가 반복되어 +24h/+48h Shadow의 입력 가용성은 별도 관찰이 필요합니다.
2. 후보 모델은 기존 공식 모델과 스케줄러에 연결하지 않았습니다.
3. 영광 archive의 결함기간 감사는 미실시로 기록되어 있어 공식 승격 전 감사가 필요합니다.
4. 국내 학술 근거가 없는 보간 상한, VIF 기준, 강건손실 선택은 학술적 정답이 아니라 프로젝트 실험 규칙입니다.

자세한 날짜별 판단과 변경 이력은 AGENTS.md와 docs/DAILY_*.md를 함께 확인하십시오.
